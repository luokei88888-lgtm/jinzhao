# 今朝 · 设计文档

- 日期：2026-09-20
- 状态：待用户审阅
- 阶段：设计（尚未进入实现）

## 1. 定位

一个 Windows 桌面小工具，一屏同时回答四件事：今天是什么日子、今天宜什么忌什么、今天天气如何、今天该穿什么。默认落在今天，可以前后翻日。

## 2. 范围

做：

- 单日聚焦界面，顶部日期栏翻日，可一键回到今天
- 黄历：农历、干支、节日、节气、宜、忌，全部本地计算
- 天气：当前温度、当日最高最低、体感温度、湿度、风、紫外线，以及未来 16 天
- 穿衣建议：本地规则推算，不依赖任何外部数据
- 城市：首次用 IP 猜一次，可手动改为任意城市，手选后固定
- 法定节假日与调休角标，年度数据自动拉取一次后落盘

v1 不做：

- 托盘常驻、开机自启（界面形态选了普通窗口）
- 系统定位权限申请（不调用 Windows 定位）
- 账号、云同步、多设备
- 手机端
- 黄历进阶信息：彭祖百忌、吉神方位、冲煞、星宿、建除十二值星（依赖库已包含这些数据，v1 不做展示）

## 3. 技术选型

- Tauri 2 + React + TypeScript + Vite，与 life-planner 同一套骨架
- 黄历依赖 lunar-typescript 1.8.6（MIT，2025-11 仍在更新，零第三方依赖）
- 所有出网代码集中在 Rust 侧，前端一行网络代码都没有
- 当前所有数据源都不需要密钥，将来若引入需密钥的源，密钥不进前端

## 5. 数据来源与实测结果

黄历：lunar-typescript 本地计算。已在类型定义中确认可用接口：getDayYi(sect?)、getDayJi(sect?)、getFestivals()、节气相关方法。注意 getDayYi 与 getDayJi 都带 sect 参数，不同取值结果可能不同，实现前必须先跑对比并固定取值，不能把不确定性留在代码里。

天气：Open-Meteo，地址 api.open-meteo.com，免密钥。实测响应 726ms，一次可返回今天起 16 天。当前字段包含温度、相对湿度、体感温度、降水量、天气代码、风速；逐日字段包含天气代码、最高最低温、体感最高最低、降水概率、紫外线指数、日出日落。需要自建 WMO 天气代码到中文的映射表，约 28 个码。

定位：IP 定位。实测 ipinfo.io 895ms 返回北京，ip-api 1997ms 返回北京。选用 ipinfo.io，因为支持 HTTPS。失败时的退路是内置默认城市北京。

节假日：优先 timor.tech 年度接口，实测 653ms、全年约 3KB，含 holiday 真假、名称、休息天数、工资倍数，补班日带 after 标记；失败换 holiday-cn 的 raw.githubusercontent 地址，实测 505ms、每年约 4KB，2025 与 2026 都有。注意它的 jsDelivr 加速地址实测连接被重置，不要用；timor.tech 走 Cloudflare，请求必须带浏览器 User-Agent，否则拿到校验页。两个源都失败或次年数据未发布（实测查 2027 返回空对象）时不报错，只隐藏角标。年度数据落盘后，当年不再联网。

关于手工补录：原设计写了「保留手工补录入口」，实现阶段决定不做。理由是为一个一年更新一次、只影响两个角标的字段做录入界面不划算。替代办法是删掉本地的 holidays-<年份>.json 再启动，程序会重新拉取；这条写进了 README。若将来数据源长期不可用，再考虑加录入界面。

## 6. 数据流

1. 启动，读本地配置：城市、上次查看的日期
2. 若没有城市：请求 IP 定位，成功则写入配置；失败则用默认北京并标记未定位
3. 前端按当前日期本地计算黄历，这一步不依赖网络
4. 若日期落在今天到第 16 天之间：查天气缓存（键为城市+日期，有效期 30 分钟）；命中直接用，未命中由 Rust 一次拉取 16 天并写入缓存
5. 若日期超出范围：天气区显示暂无预报，黄历照常
6. 节假日表：本地已有当年数据就直接用；没有则拉取一次并落盘
7. 合并渲染

## 7. 界面

窗口约 420×620，可缩放，最小 360×520。

- 顶部日期栏：左箭头、日期与星期、右箭头，右侧一个"回到今天"
- 日期下方是城市按钮，点击展开北京、唐山与搜索框
- 黄历区：第一行农历与干支；第二行节日或节气，有才占位；第三行宜，第四行忌，均为流式排列，超过 8 条折叠成"等 N 项"
- 天气区：温度、天气现象、当日最高最低、体感温度；下方一行小字放湿度、风、紫外线；再下方单列一句穿衣建议
- 底部未来三天条：日期、图标、最高最低温，点击跳到那天。这里不显示宜忌，避免脱离上下文造成误判
- 休班角标固定显示在日期栏右侧，用两个小标记区分休假与补班

## 8. 穿衣规则

以体感温度为准，不看气温。白天取当日体感最高值，早晚取体感最低值。

分档（体感温度，摄氏度）：

| 区间 | 建议 |
| --- | --- |
| ≥ 28 | 短袖短装 |
| 24 – 27.9 | 短袖 |
| 20 – 23.9 | 长袖 |
| 16 – 19.9 | 薄外套 |
| 11 – 15.9 | 夹克或风衣 |
| 5 – 10.9 | 毛衣加外套 |
| 0 – 4.9 | 厚外套 |
| < 0 | 羽绒加保暖内层 |

输出规则：两档相同则输出一句；不同则输出"白天 X，早晚 Y"。

附加提示：降水概率不低于 50% 提醒带伞；紫外线不低于 6 提醒防晒；体感温差不低于 10 度提醒早晚加衣；风速不低于 30 公里每小时提醒防风。

函数签名草案：

%%%
type DressInput = { feelsMax: number; feelsMin: number; precipProb: number; uvMax: number; windMax: number };
type DressResult = { dayTier: Tier; nightTier: Tier; sentence: string; tips: string[] };
%%%

所有阈值做成常量表，方便测试和调整。

## 9. 错误处理

原则：任何网络问题都不能拦住黄历。黄历是本地计算的地基，天气是附加物。

- 天气请求失败：有缓存则显示上次数据并标注时间；无缓存则提示联网后自动重试。不弹窗、不用错误色
- IP 定位失败：回退默认城市北京，城市按钮标记未定位，可手动修改
- 日期超出预报范围：显示"这一天还没有预报"，属于正常状态
- 节假日接口失败或次年数据未发布：隐藏休班角标，其余照常；需要强制刷新时删除本地节假日表再启动
- 缓存或配置文件损坏：删除并按默认值重建，不能让启动卡住
- 首次启动无网络：应用必须能正常打开，显示黄历与默认城市

## 10. 测试策略

- 黄历对照抽样：不少于 20 天，覆盖不同月份、节气当天、农历月初与月末，与权威来源比对
- sect 参数对比：先跑两个取值看清差异，固定一个再写实现
- 穿衣规则：表驱动测试加边界值，重点测体感 28 度、16 度、温差 10 度这几个分档点
- 天气解析：用真实响应做样本，另补缺字段、空数组、null 三种变体
- 日期边界：跨日、跨月、跨年、闰年 2 月 29 日
- 失败路径手工验证：断网打开、删除缓存文件、把缓存改成非法 JSON、系统时间前推 31 分钟验证缓存过期
- Rust 网络层不写单元测试，用失败路径手工验证替代
